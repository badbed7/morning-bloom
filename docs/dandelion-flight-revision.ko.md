# 홀씨 바람놀이 재설계 · 구현 규칙

작성: 2026-09-29. 상태: **구현 완료**.

이 문서는 v0.8.2의 민들레 씨앗 여행을 대체한 규칙과 구현 기준이다. 이전 여행 구현은 `de84a33`, 복원한 상하 비행은 v0.8.1의 `455d0d1`에서 확인했다.

## 1. 확정된 방향과 첫 적용 수치

사용자 요청으로 확정된 방향은 다음과 같다.

- 누르거나 길게 눌러 홀씨를 날리는 기존 조작을 유지한다.
- 천장이나 땅에 닿아도 죽지 않고 비행을 계속한다.
- 비행 중 고리에 닿으면 골드를 얻는다.
- 진행도 100%에서 민들레를 내 정원에 추가한다.
- 100% 달성 기준은 **유효 플레이 누적 1시간**이다. 중간에 나가도 이어 할 수 있다.
- 햇빛과 골드는 적게 지급한다. 잠정 제안했던 3분 완료·고리마다 1G는 폐기한다.

누적 1시간은 사용자 확정값이다. 고리 보상 비율·간격·민들레 판매가는 적은 보상을 구현하기 위한 첫 제안값이며, 플레이 검수에서 조정한다.

| 항목 | 적용 기준 |
| --- | --- |
| 한 여행 | 유효 플레이 누적 3,600초, 1시간. 여러 번 나눠 플레이 가능 |
| 고리 보상 | 접촉마다 보상 진행량 1개 적립, 누적 10개마다 1G 즉시 지급 |
| 고리 간격 | 같은 지점을 약 10초 간격으로 통과하도록 배치 |
| 완료 보상 | 다 자란 민들레 1송이와 햇빛 1개. 추가 완료 골드는 없음 |
| 민들레 기본 판매가 | 1G. 보관과 판매는 사용자가 선택 |
| 실패·입장 비용·횟수 제한·재시작 대기 | 없음 |

한 여행은 고리 점수와 무관하게 100%까지 진행된다. 고리를 놓쳐도 꽃 획득이 막히지 않는다. 100%에서는 정상 완료로 여행을 마치고, 다음 여행은 사용자가 즉시 시작할 수 있다. 자동으로 다음 여행을 시작하지 않는다. `10개당 1G`는 접촉당 소수점 골드를 도입하는 대신 기존 정수 재화를 유지하는 저보상 정산안이다.

## 2. 플레이 흐름

1. 메인 화면의 `홀씨놀이`를 누르면 비행장과 저장된 진행도가 보인다.
2. 비행장, 바람 버튼 또는 스페이스를 누르면 시작한다. 첫 입력부터 홀씨가 반응한다.
3. 누르면 상승하고 놓으면 내려온다. 고리와 배경은 계속 왼쪽으로 흘러 전진을 표현한다.
4. 고리에 닿으면 작은 수집 효과와 `골드 1G까지 7/10` 같은 진행 표시를 갱신한다. 10개를 채운 접촉에서만 `+1G` 효과가 나온다.
5. 누적 1시간으로 100%가 되면 민들레 한 송이와 햇빛 1개가 저장된다. `정원에 민들레가 피었어요 · 햇빛 +1`과 `한 번 더`를 표시한다.
6. `한 번 더`는 대기 없이 새 여행을 시작한다. 받은 골드·햇빛·꽃과 아직 골드로 바꾸지 못한 고리 적립량을 유지한다.

중간에 닫으면 받은 보상과 두 진행도(민들레까지 누적 시간, 1G까지 고리 적립량)를 보존한다. 예를 들어 15분씩 네 번 플레이하면 민들레를 얻는다. 다시 열면 남은 시간부터 이어 하되, 홀씨 위치는 중앙의 안전한 위치로 배치하고 고리는 새로 생성한다. 정확한 비행 좌표까지 저장하지 않는다.

## 3. 조작과 비행 물리

v0.8.1의 `WindState`에 있던 높이 `y`, 수직 속도 `velocity`, 바람 `wind`, 고리 이동을 복원한다. v0.8.2처럼 진행률을 홀씨의 화면상 x좌표로 바꾸는 방식은 사용하지 않는다. 홀씨의 x좌표는 화면 약 28% 지점에 유지한다.

- 마우스 왼쪽 버튼, 비행장 누르기, 스페이스가 같은 입력으로 동작한다.
- 짧은 클릭도 즉시 작은 상승 반응을 준다. 첫 제안은 누름 시작 시 수직 속도를 최소 위쪽 `0.18 화면 높이/초`로 보정하는 방식이다. 연타가 무제한 가속을 만들지 않게 속도 상한을 둔다.
- 길게 누르면 바람이 부드럽게 강해져 상승하고, 놓으면 관성과 중력으로 내려온다. 기존 바람 반응 시간 0.18초를 출발점으로 사용한다.
- 여러 입력을 동시에 사용하면 하나라도 눌린 동안 바람을 유지한다. 키보드 자동 반복은 새로운 클릭으로 계산하지 않는다.
- 천장·바닥에 닿으면 화면 안으로 위치를 보정하고 수직 속도를 안쪽으로 약하게 반사한다. 첫 반사 계수는 0.25다. 접촉 위치에 고정되거나 화면 밖으로 나가지 않아야 한다.
- 경계 접촉은 진행도, 골드, 고리 또는 한 판 상태를 초기화하지 않는다. 목숨·게임 오버·충돌 손실을 추가하지 않는다.

시간은 `time.monotonic()`으로 측정한다. 물리는 기존처럼 최대 1/120초 간격으로 나누어 계산하며, 한 번에 처리하는 경과 시간은 0.1초까지 반영한다. 긴 프레임 정지·절전 후 복귀가 순간 이동, 여러 보상 또는 갑작스러운 완료로 이어지지 않도록 한다.

## 4. 고리 접촉과 골드

고리는 오른쪽에서 왼쪽으로 이동한다. 위아래 위치를 변화시키되 중심은 비행장 높이의 22~78% 안에 두고, 앞 고리와의 높이 차이를 제한해 조작으로 도달할 수 있게 한다. 첫 버전은 속도와 크기를 일정하게 유지한다.

판정은 **고리의 내부 또는 테두리에 홀씨가 닿는 것**이다. 이전 코드의 `x좌표를 지나가는 한 순간에 중심이 안쪽인지 확인`하는 좁은 판정 대신, 보이는 고리 타원과 홀씨 판정 영역의 겹침을 매 물리 단계에서 확인한다. 영역을 소폭 넓히되 그림과 다른 곳에서 보상받지 않도록 시각 검수한다.

- 각 고리는 `collected` 표시를 가지며 수집 수를 한 번만 올린다. 여러 프레임 겹치거나 왕복해도 추가 적립하지 않는다.
- 놓친 고리는 화면 밖으로 사라진다. 감점·진행도 손실 없이 다음 고리가 온다.
- 골드는 고리 수집 수가 10의 배수가 되는 즉시 게임 공용 `Garden.coins`에 1G를 반영한다. 여행 종료 때 몰아서 지급하지 않는다. 10개를 채우기 전에도 수집 효과와 적립 진행 표시로 접촉을 확인할 수 있다.
- 고리 재등장 간격과 첫 고리 도착 시간을 같은 기준으로 잡는다. 창을 계속 닫고 열어 첫 고리만 빨리 받는 경로를 만들지 않는다.
- 완료 8G를 별도로 지급하던 v0.8.2 규칙은 제거한다. 골드는 고리 적립으로, 완료 보상은 민들레와 햇빛 1개로 얻는다.

경제 검수: 약 10초에 고리 1개, 수집 10개당 1G이면 시간당 최대 약 36G다. 성공률 50%에서는 약 18G다. 누적 1시간 완료의 직접 보상은 민들레 한 송이와 햇빛 1개이며, 민들레까지 판매해도 골드는 시간당 최대 약 37G다. 이는 첫 제안의 최대 약 520G/시간보다 크게 낮다. 기존 정원에서 생산되는 햇빛은 별도이며, 민들레도 기존 생산 간격과 대기 상한을 따른다. 접속·완료 연출·고리 한 개마다 별도 햇빛이나 보너스 골드를 중복 지급하지 않는다.

## 5. 100%와 민들레 수집

진행률은 `min(1, 누적 유효 플레이 초 / 3600)`이다. 바람을 놓고 내려오는 시간도 조작의 일부이므로 포함한다. 시작 전, 일시정지, 다른 앱으로 전환, 창 최소화·닫기, PC가 꺼진 동안은 포함하지 않는다. 컴퓨터 시각 변경과 개발자 `+6시간`도 포함하지 않는다. 닫기나 재실행은 누적 시간을 초기화하지 않는다.

실행 중에는 단순히 클릭 횟수나 고리 수를 요구하지 않는다. 따라서 여행을 시작한 뒤 창을 활성 상태로 유지하면 고리를 못 먹어도 누적 1시간에 민들레 한 송이를 얻을 수 있다. 무인 상태에서 연속으로 꽃이 생성되지 않도록 다음 여행에는 새 시작 입력이 필요하며, 계속 누르고 있던 입력은 새 시작으로 취급하지 않는다.

100% 도달 시 다음 변경을 **한 번의 로컬 저장으로 함께 확정**한다.

1. `collection`에 완성된 `dandelion` 한 송이를 추가한다.
2. `sunlight`에 1을 더한다. 별도의 수집 토큰으로 중복 생성하지 않는다.
3. `last_wind_reward_id`에 완료한 여행의 식별자를 기록한다.
4. `wind_progress`를 0으로 되돌려 다음 여행을 준비한다. 고리 적립 수는 초기화하지 않는다.

새 민들레는 수확한 꽃과 같은 개체 형식과 고유 ID를 사용한다. 같은 품종을 여러 송이 모을 수 있으며, 재배 화분이 가득 차 있어도 정원에 추가된다. 기존 정원의 햇빛 생산, 드래그 판매, 화분 스킨, 바탕화면 플로팅을 그대로 지원한다. 꽃을 추가하기 전에 기존 정원의 시간 진행을 처리하고, 첫 정원 꽃이면 햇빛 생산 타이머를 시작한다. 완료 햇빛 1개를 이미 직접 지급하므로 `sun_intro_claimed`도 함께 처리해 최초 꽃의 안내용 햇빛 토큰을 추가로 지급하지 않는다.

민들레는 보상 전용 품종이다. `PLANTS`에는 추가하되 `REGULAR_PLANTS`와 랜덤 씨앗 확률에는 넣지 않는다. 외관은 앞서 제공된 레퍼런스의 노란 다겹 꽃잎·노란 꽃심·톱니 모양 잎을 따른다. 비행 중의 흰 홀씨와 정원에 핀 노란 민들레를 구분한다.

## 6. 화면 구성

위에서부터 다음 순서로 배치한다.

1. `홀씨 바람놀이` 제목과 닫기 버튼.
2. 남은 누적 플레이 시간, `1G까지 7/10` 고리 적립 표시.
3. `민들레까지 45%` 진행 게이지. 끝의 작은 화분 아이콘은 완료 보상을 나타낸다.
4. 상하 조작이 가능한 비행장. 홀씨, 움직이는 고리, 바람, 경계 접촉 효과를 표시한다.
5. `누르면 상승 · 놓으면 하강 · 고리 10개마다 1G` 안내와 바람 버튼. 완료 보상은 `누적 1시간 · 민들레 1송이 + 햇빛 1`로 표시한다.

목적지 화분은 상단 게이지의 목표 표시로 옮긴다. 비행장 가장 오른쪽의 화분까지 홀씨가 한 시간 내내 조금씩 이동하는 연출은 제거한다. 완료 시 비행장에 민들레 화분을 표시한다. 완료 화면에서 버튼을 누르고 있던 상태가 다음 여행으로 넘어가지 않게 입력을 비운다.

본체 불투명도·최상단 여부·제목 드래그·Esc 닫기를 유지한다. 320px와 384px 너비에서 게이지·시간·버튼이 겹치지 않는지 캡처로 검수한다. 게임 플레이 화면과 완료 화면을 함께 검수한다.

## 7. 기존 코드에 맞춘 구현 분담

별도 게임 엔진이나 보상 서비스는 만들지 않고 현재 모듈을 수정한다.

| 파일 | 담당 변경 |
| --- | --- |
| `python/morning_bloom/wind_game.py` | 상하 비행 복원, 경계 반사, 고리 접촉, 누적 3,600초 진행, 실행·일시정지·보상 저장 대기·완료 상태, 화면과 입력 |
| `python/morning_bloom/model.py` | 고리 적립과 10개당 1G 지급, 민들레와 햇빛 1개 지급, 진행도·중복 지급 검증 |
| `python/morning_bloom/app.py` | 미니게임 신호 연결, 기존 `act()`를 통한 저장·실패 복구, 정원 갱신, 문구 변경 |
| `python/morning_bloom/plant_catalog.py` | 보상 전용 민들레 정의. 상점 품종 목록은 유지 |
| `python/morning_bloom/flower_art.py` | 공통 민들레 그림. 정원·판매 미리보기·플로팅이 같은 그림 사용 |
| `python/morning_bloom/storage.py` | v12 진행도 변환, v13 이전과 원본 백업 |
| `python/tests/test_wind_and_flowers.py` | 기존 여행 테스트를 새 비행·보상·이전 기준으로 변경 |

`WindState`는 화면과 무관하게 물리·고리·진행도를 계산한다. `WindGame`은 입력을 전달하고 이벤트를 내보내며, `Garden`과 `Store`만 영구 보상을 확정한다. 다음 계약으로 연결한다.

- `progressed(progress_seconds)`: 현재 판의 진행도를 전달한다.
- `ring_collected(game_id, total_hits)`: 보상 처리를 요청한다. 골드 금액은 UI에서 받지 않고 모델 상수로 결정한다.
- `completed(game_id)`: 민들레와 햇빛 지급을 요청한다. 기존 `(game_id, coins)` 완료 신호를 교체한다.
- `reward_result(success, text)`: 저장 성공 후 수집 표시를 확정하거나, 실패한 이벤트만 같은 값으로 재시도한다.

고리 이벤트에는 저장된 누적 수집 수에 1을 더한 `total_hits`를 사용한다. 모델은 정확히 다음 값만 허용하고, 이미 처리한 값이나 건너뛴 값은 거절한다. 지급량은 `total_hits // 10 - wind_ring_hits // 10`으로 계산한 뒤 수집 수를 갱신한다. 화면의 적립량은 `wind_ring_hits % 10`으로 계산하므로 별도 소수점 골드나 적립 필드가 필요 없다. `app.py`는 현재 열린 게임·저장 파일·일반/개발자 모드가 이벤트의 소유자와 일치하는지도 기존 방식으로 검사한다.

모델의 `reward_wind()` 완료 골드 지급은 민들레·햇빛을 추가하는 `complete_wind(game_id, now)`로 교체했다. 고리에는 `reward_wind_ring(total_hits)`를 둔다. 완료한 민들레의 꽃 등록과 햇빛 타이머 초기화는 수확과 같은 규칙을 따르며, 재배 화분 비우기와 안내용 햇빛 토큰 추가는 수확에만 남긴다.

## 8. 저장, 실패 복구, 기존 사용자 이전

첫 구현의 저장 스키마는 v13으로 올린다. 추가 필드는 `wind_ring_hits` 하나이며, 일반/개발자 정원 각각의 영구 누적 고리 수집 수를 0 이상의 정수로 저장한다. 골드는 기존 `coins`, 햇빛은 기존 `sunlight`, 꽃은 기존 `collection`을 사용한다. 비행 위치·고리 목록은 영구 필드로 늘리지 않는다. 1G가 되기 전 고리 1~9개도 재실행·완료·새 여행 사이에서 보존한다.

- v12의 `wind_progress`는 `기존 진행도 / 7200 * 3600`으로 변환한다. 예: 기존 3,600초는 새 기준 1,800초, 즉 50%다. 저장된 100%는 새 규칙으로 민들레·햇빛을 한 번 지급할 수 있는 완료 대기 상태로 연다.
- 이전에는 `wind_ring_hits = 0`을 추가한다. 기존 골드·꽃·배치·인증 정보는 바꾸지 않는다.
- `last_wind_reward_id`는 보존한다. v0.8.2에서 이미 지급한 골드를 다시 회수하거나 꽃으로 소급 지급하지 않는다.
- `wind_upgrade` 값은 호환성을 위해 보존하되, 이번 누적 1시간 기준에는 배수를 적용하지 않는다. 현재 강화 구매 UI는 없으며, 강화 효과는 후속 강화 기획에서 다시 정의한다.
- v1~v11도 v13까지 순서대로 이전한다. 현재 `Garden.to_dict()`의 키로 옛 스키마를 검사하는 코드와 중간 버전 검증 호출도 함께 수정해 신규 필드 때문에 옛 저장을 거절하지 않게 한다.
- 첫 저장 전에 원본을 `.json.v12-migration.bak` 등 기존 버전별 백업 규칙으로 보존한다. Google Drive 복원에도 동일한 이전과 검증을 적용한다.

고리 수집 수와 해당 접촉의 골드 지급을 기존 `act()`와 `Store.save()`로 함께 즉시 저장한다. 1G가 생기지 않은 접촉도 적립량을 저장한다. 민들레·햇빛·완료 기록·진행도 초기화 역시 한 번에 저장한다. 시간 진행도는 기존 30초 자동 저장과 창 닫기 저장을 사용한다. 정상 종료 시 진행도를 보존하며, 강제 종료 시 보상 없는 구간의 진행도는 마지막 저장 이후 최대 약 30초가 손실될 수 있다.

보상 저장 실패 시 해당 변경을 되돌리고 그 이벤트를 대기 상태로 유지한다. 비행과 추가 보상은 잠시 멈추고 `저장 다시 시도`를 제공한다. 100% 완료 저장 실패는 100%를 유지한다. 저장 성공 전에는 고리 적립·골드·햇빛·꽃 획득을 확정 표시하지 않는다. 종료나 재시도로 같은 이벤트를 두 번 지급하지 않는다.

같은 물리 단계에서 고리 접촉과 100%가 겹치면 고리 보상을 먼저 확정한 다음 완료를 처리한다. 고리 저장이 실패하면 완료 처리를 보류한다. 완료만 실패한 경우 이미 저장한 고리 골드는 보존한다. 콜백이 재진입해 순서가 바뀌지 않게 대기 이벤트는 하나씩 처리한다.

완료 저장 후 다음 판의 새 입력에서 UI 진행도를 0으로 동기화한다. 이전 판의 100% `progressed` 이벤트가 뒤늦게 와서 진행도를 되살리지 않도록 완료 상태와 현재 판 ID를 검사한다. 일반/개발자 모드 전환이나 클라우드 복원은 기존처럼 열린 미니게임을 닫은 뒤 수행한다.

## 9. 개발 순서와 완료 기준

1. **비행 복원**: 입력·상승/하강·고리 렌더링을 복원하고 천장/바닥 사망을 반사로 변경한다. 짧은 클릭과 길게 누르기 모두 체감 반응을 확인한다.
2. **누적 진행과 고리 보상**: 3,600초 게이지, 고리 접촉별 적립·10개당 1G, 중복 차단, 정지·재개·저장 실패 처리를 연결한다.
3. **민들레와 저장 이전**: 보상 전용 품종·공통 그림·정원 추가·완료 햇빛 1개·v13 이전을 구현한다.
4. **UI와 경제 검수**: 320/384px 비행·완료 화면, 짧은 플레이를 여러 번 이어 하는 흐름, 고리 수익과 화분 구매 속도를 검수한다. 누적 1시간은 확정 기준이며, 고리 10개당 1G·10초 간격·완료 햇빛 1개·판매 1G는 이 단계에서 검수한다.

필수 회귀 검증은 다음과 같다.

- 천장·바닥에 여러 번 닿아도 플레이가 끝나지 않고, 반대 조작으로 벗어날 수 있다.
- 홀드를 놓아도 비행·고리 이동·진행도는 이어지며, 창 비활성화·최소화에는 모두 정지한다.
- 같은 고리에 수십 프레임 겹쳐도 한 번만 적립하고, 놓치면 손실 없이 계속한다. 고리 9개에서는 0G, 10개에서 1G, 20개에서 누적 2G다.
- 고리 9개를 모은 뒤 닫기·재실행·여행 완료를 거쳐도 다음 고리 한 개로 1G를 받는다.
- 3,599.9초에서는 완료 보상이 없고 3,600초에서 정확히 민들레 한 송이와 햇빛 1개가 생긴다. 15분씩 네 번 플레이한 결과도 같으며, 같은 완료 이벤트 재전송과 재실행에는 중복 지급하지 않는다.
- 100%에서 민들레와 햇빛이 추가되고 완료 화면을 유지한다. 새 시작 입력 전에는 다음 완료 보상을 자동 지급하지 않는다.
- 고리와 완료가 겹친 프레임, 저장 실패·재시도·강제 종료 경계에서 저장된 고리 수·골드·햇빛·꽃 수가 일치한다.
- 중간 진행도·골드·꽃의 재실행 복원, v12의 50%/100% 이전, v1~v11 연쇄 이전, 미래 스키마 원본 보호를 확인한다.
- 민들레 정원 표시·햇빛 생산·판매·스킨·플로팅이 기존 꽃과 같은 경로로 동작하고, 상점과 랜덤 씨앗에 민들레가 추가되지 않는다. 첫 정원 꽃이 민들레여도 완료 햇빛 1개 외에 안내용 토큰을 중복 지급하지 않는다.
- 개발자 정원과 일반 정원의 진행·보상을 섞지 않으며, 게임 도중 클라우드 복원·종료 요청에서 오래된 이벤트를 무시한다.

게임 코드와 저장 스키마 v13에 반영했다. 릴리스 번호는 별도 릴리스 작업에서 정한다.
