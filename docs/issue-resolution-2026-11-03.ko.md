# 2026-11-03 열린 이슈 구현 및 검증

대상: #1, #2, #7, #8. 기준 소스 v0.8.10 이후. 기존 초안 PR #3의 20칸·주간 주사위 규칙을 병합하지 않고 최신 60칸·주사위 2개·햇빛 결제를 유지한다. 이 문서는 공개 배포 완료를 의미하지 않는다.

## #1 홀씨 바람놀이 강화

과거 이슈의 2시간·8G는 최신 구현과 다르므로 현재 1시간·민들레 1송이·햇빛 1개 규칙을 기준으로 구현했다. 누르기 여부와 관계없이 공중에서 수평 이동하는 동안 누적하며 바닥·일시정지·비활성 창에서는 정지한다. 새 창 진입은 시작 전이고 held input은 비어 있다.

| 강화 | 단계 | 효과 | 다음 단계 가격 |
| --- | --- | --- | --- |
| 이동 속도 | 0~10 | 진행·고리 이동·고리 생성에 `1.15^단계` 적용, 최대 약 4.05배 | 현재 단계 n에서 `20×(n+1)^2` G |
| 고리 골드 | 0~5 | 고리 10개마다 `1+단계` G | `40×(n+1)^2` G |

구매 전 현재/다음 효과·가격 표시, 골드 부족/최대 단계 거부, 저장 실패 시 단계·골드 복원. 구매 시 비행을 일시정지하여 다음 입력부터 새 효과를 적용한다. 기존 속도 강화 단계는 그대로 이어받는다. 남은 비행 시간 표시는 속도 배율을 반영한다.

경제 기준: 고리를 빠짐없이 얻는 이상적 기본 속도에서 약 100초당 1G, 시간당 36G다. 속도 1단계의 추가 기대 생산은 5.4G/시간으로 20G 회수에 약 3.7시간, 보상 1단계는 추가 36G/시간으로 40G 회수에 약 1.1시간이다. 실제로는 고리 누락·바닥 정지로 더 오래 걸린다. 민들레·햇빛·오프라인 보상을 추가 증폭하지 않는다. 7일 실제 플레이 경제 평가는 자동 검사로 대체하지 않는다.

## #2 128종 실제 사용과 영구 도감

- 도감 식물 22 / 정원 83 / 화분 45 = 150종. 기존 기본 5종의 중복 ID를 만들지 않는다.
- 보상 풀은 식물 신규 8 / 정원 82 / 화분 44 = 134종. 일반 12종·고대 꽃·민들레와 기본 잔디·토분은 기존 획득 경로를 유지한다.
- 신규 식물 첫 획득은 영구 재배 해금과 씨앗 1개를 함께 지급한다. 해금 뒤 골드로 씨앗 재구매 가능. 중복은 교환잎만 지급한다. 랜덤 씨앗의 고대 0.1% 풀은 바꾸지 않는다.
- 신규 배경·화분은 영구 소유·무료 재적용, 직접 구매 거부. 기존 로즈는 SSR 뽑기 전용, 과거 소유권 유지.
- 최초 개화 발견은 판매 후에도 남는다. 가챠 해금과 개화 발견을 구분한다. 구버전은 현재 보관 꽃과 이미 개화한 화분에서 증명 가능한 발견만 복원한다.
- 도감과 실제 렌더링에 같은 벡터 아트를 사용한다. 과거 시트의 카드 테두리·가격·글자를 게임 화면에 잘라 붙이지 않는다. 기존 초안 PR #3의 독립 벡터 렌더러를 재사용했고 경제·저장·장비 효과 모듈은 가져오지 않았다.
- 정원·화분 선택은 페이지로 이동한다. 소유·사용 중·미보유·등급·획득 경로를 도감과 상점에서 구분한다.
- 이번 수집 확장은 꾸미기만 제공한다. #2의 최신 범위가 후속으로 분리한 성장·판매·크기 능력치 장비 및 여러 특수 보드는 추가하지 않는다. 공통 바탕화면 크기는 #7의 사용자 설정이다.

### 확률과 수집 비용

일반 R 70% / SR 25% / SSR 5%, 은색 칸 또는 10회 보장 SR 95% / SSR 5%, 금색 칸 또는 60회 보장 SSR 100%를 유지한다. 같은 등급 안에서는 개별 가중치가 모두 1이다. 세 분류의 천장은 공유하며 변경·추첨 창 재진입으로 초기화하지 않는다. 보상 전체 명세는 [항목·등급표](collection-items.ko.md)에 고정한다.

| --- | --- | ---: | ---: |
| 식물 | 3 / 3 / 2 | 2.5000% | 신규 분류 |
| 화분 | 14 / 15 / 15 | 0.3333% | 5% |
| 정원 | 27 / 28 / 27 | 0.1852% | 5% |

로즈·기존 라벤더 정원은 동일 등급 풀 확대로 개별 확률이 낮아진다. 보장 시에는 위 일반 칸 수치가 아닌 해당 보장 등급 확률을 등급 내 항목 수로 나눈다. 앱은 등급별 개수와 조건부 개별 확률을 함께 안내한다.

## #7 문구·개발자 모드·크기

- 상점/창 제목에서 60칸 고지 제거. 진입 `주사위 굴리기`, 위치 `현재 N번`, 실행 `주사위 굴리기 · 햇빛 10`. 실제 주사위 2개와 경로·특수 칸 번호는 유지한다.
- 테스트 정원 기본 무한 햇빛. 세션 토글만 사용하며 일반 정원에서는 거부한다. `∞ · 테스트`를 표시하고 원장의 햇빛 정수·무료권은 보존한다. 뽑기와 일반 햇빛 꾸미기 구매에만 적용하고 로즈·신규 보상의 뽑기 전용 제한, 골드·교환잎·비료 상한은 유지한다.
- 크기는 전 바탕화면 꽃 공통 50~200%, 10% 단위, 기본 100%. 화면 배율과 별도로 그림·창·마스크·햇빛 클릭 좌표를 함께 변환한다. 크기 변경 중 드래그/누름을 취소한다. 기존 좌상단 위치를 기준으로 조정하고 Windows 호스트가 가상 데스크톱 경계 안에 보정한다. 최소 배율에서도 햇빛 좌표를 역변환해 수집한다.
- 저장 schema 15. v14 형식의 키 집합을 고정하고 이전의 중간 검증도 최종 v15까지 이어지도록 수정했다. v1~v14 이전, 알려진 과거 가챠 이력·로즈·배치·재화·천장을 유지한다.

## #8 Google Drive 오류 분류와 재시도

- HTTP 실패의 단계 `token/list/create/upload/download/profile`, status, OAuth code, Drive reason/location을 구조화해 화면과 안전한 진단 로그에 남긴다. 토큰·secret·이메일·정원 원문·서버 임의 설명은 로그에 넣지 않는다.
- `invalid_grant` 및 OAuth client ID 변경은 재연결 필요로 전환하고 자동 재시도를 멈춘다. 재연결 필요 표식과 client ID를 Windows 자격 증명에 저장한다. 기존 client ID 메타데이터가 없는 자격 증명은 첫 정상 갱신 후 연동한다.
- Drive 401은 access token을 비우고 갱신하여 한 번 재시도한다. 429/일시적 5xx 등 읽기·업로드 HTTP 요청은 최대 3번이다. POST 파일 생성은 중복 생성 위험 때문에 HTTP 자동 재시도를 하지 않는다. 네트워크 실패는 다음 자동 백업 주기에 재시도한다.
- 영구 설정/권한 오류는 자동 백업을 중지하고 설정 안내를 표시한다. 수동 재시도가 정상 완료되면 자동 백업을 재개한다.
- callback 없음·state 불일치·로그인 취소·브라우저 열기 실패를 구분한다. state와 PKCE 검증을 유지한다.
- 공개 빌드는 OAuth ID/secret을 모두 요구한다. 의도적인 로컬 전용 빌드는 `BLOOM_CLOUD_DISABLED=1`로 명시하고 배포 사용 안내에도 표시한다. 설정값은 빌드 로그에 출력하지 않는다.
- 종료 백업 실패 시 로컬 저장·미완료 동기화 표식은 유지하고, 재연결은 필요한 오류에만 안내한다. 클라우드 파일 삭제·scope 확대·업로드 메서드 변경은 하지 않는다.

실제 사용자 장애의 원인은 이전 스크린샷만으로 확정하지 않았다. 실제 오류 stage/status/code, Google Auth Platform Testing/Production 상태, Windows 로그인→백업→재실행→복원은 계정·실기 검증이 남는다. 따라서 #8은 코드 보완 후에도 이 검증이 끝날 때까지 열린 추적으로 유지한다.

공식 근거: [데스크톱 OAuth](https://developers.google.com/identity/protocols/oauth2/native-app), [Drive 오류 처리](https://developers.google.com/workspace/drive/api/guides/handle-errors).
