# 실행 중 업데이트 · v0.8.12

이슈 #10 구현. 새 런처는 게임이 켜져 있는 동안 5분마다 공개 Release를 확인하고, 설정의 ‘업데이트 확인’으로 즉시 확인할 수 있다. 다운로드·검증·별도 디렉터리 설치·격리 실행 검사 중 기존 게임과 현재 버전 포인터는 유지된다.

## 사용자 흐름

1. 확인·다운로드 진행과 현재 버전은 설정의 ‘게임 업데이트’에 표시한다.
2. 준비가 끝나면 본체에 ‘업데이트 준비 완료’와 ‘지금 적용 / 나중에’를 표시한다.
3. ‘나중에’는 알림을 숨기고 플레이를 유지한다. 설정에서 다시 적용할 수 있다. 다음 수동 실행에도 준비본을 재사용한다.
4. ‘지금 적용’은 미니게임·가챠 연출을 정리하고 정원을 저장한다. 거래 입력을 잠근 뒤 런처에 적용 준비를 요청한다.
5. 기존 종료 경로로 로컬 저장과 진행 중 클라우드 작업을 마친다. 저장 실패 또는 종료 확인 통신 실패는 적용을 취소하고 게임을 유지한다.
6. 종료가 수락되면 런처에 최종 확인을 보내고 플로팅 창·타이머·정원 잠금을 해제한다. 런처는 실제 프로세스 종료 코드 0을 확인한 뒤에만 새 버전을 활성화하고 자동 실행한다.
7. 일반 정원/개발자 정원 선택도 새 프로세스로 전달한다. 일반 종료는 자동 재실행을 요청하지 않는다.

## 구조와 상태

- `Installer.stage()`는 해시·압축 경로·필수 파일·격리 시작 검사를 거쳐 버전별 디렉터리를 준비한다. `activate()`가 현재 포인터를 원자적으로 전환한다. 기존 `install()`은 시작 시 두 단계를 이어 사용한다.
- 런처의 `Coordinator`가 다운로드와 준비 상태를 소유한다. 한 번에 하나만 준비하고, 먼저 준비된 버전은 적용하거나 다음 수동 실행할 때까지 고정한다. 더 최신 버전으로 준비본을 중간에 바꾸지 않는다.
- `pending-update.json`과 버전/해시별 ZIP을 저장한다. 다음 실행에도 manifest·ZIP 검증 후 재사용한다. 불완전 다운로드는 준비 완료로 인정하지 않는다.
- 네트워크/설치 오류는 상태에 표시하고 5분 주기에 재시도한다. 준비 실패가 기존 게임을 종료하지 않는다.
- 게임과 런처는 `127.0.0.1` 임의 포트와 실행 세션별 256비트 토큰으로 통신한다. 고정 명령만 허용하며 실행 경로나 파일 경로를 받지 않는다. 게임의 로컬 요청은 프록시를 사용하지 않고 2초 제한을 둔다. 토큰을 로그나 UI에 표시하지 않는다.
- 클라이언트의 상태·적용 준비 요청은 백그라운드 스레드에서 처리한다. 실제 종료 직전 확인만 로컬 요청의 최대 2초 제한 안에서 동기 처리한다.
- 새 버전 시작 검사는 별도 임시 정원과 offscreen Qt로 실행하여 사용자 정원과 플레이 창을 사용하지 않는다. Python 의존성이 다르면 별도 requirements 해시별 실행 환경을 준비한다.

## 저장·복구

- 가챠 결과 등 이미 확정된 거래는 재추첨하지 않는다. 적용 중 새 거래는 거부한다. 정원 데이터·배치·꽃 크기·강화·설정은 기존 저장을 사용하며 이번 기능은 schema를 바꾸지 않는다.
- Drive 실패 시 기존 #8 종료 처리로 로컬 저장과 미동기화 표식을 남긴다. 실패를 클라우드 성공으로 표시하지 않는다. 계정 실제 장애 원인 검증은 별도다.
- 게임이 종료된 다음 활성화 직전에 정원 폴더의 JSON·백업·미동기화 표식을 런처의 `save-backups/<id>`에 복사한다. 복사 실패 시 활성화를 중단하고 이전 버전을 다시 연다.
- 새 프로세스가 시작 확인 전 오류로 종료되면, 저장 파일 목록과 바이트 해시가 업데이트 전과 완전히 같을 때만 이전 포인터로 되돌려 한 번 재실행한다.
- 저장이 바뀌었거나 schema가 올라간 경우 자동으로 구버전을 실행하거나 백업을 덮어쓰지 않는다. 새 저장·기존 설치·업데이트 전 백업을 보존하고 오류를 안내한다. 수동 복원이 필요하면 호환되는 백업을 선택해야 한다.
- 일반 종료·취소·비정상 종료는 최종 적용 확인이 없으므로 새 프로세스를 중복 생성하지 않는다.

## 최초 설치 및 호환

**최초 한 번은 v0.8.12의 전체 ZIP을 새 폴더에 압축 해제하고 그 폴더의 BAT 또는 런처로 실행해야 한다.** 기존 런처 자체는 게임 payload 업데이트로 교체되지 않는다. 이전 런처로 새 게임만 받거나 게임 EXE를 직접 실행하면 기능을 비활성화하고 새 런처 실행 안내를 표시한다. 정원 저장 폴더는 지우지 않는다.

이후 같은 새 런처로 실행한 게임에서는 후속 공개 버전을 실행 중 다운로드하고 적용할 수 있다. 재시작 없는 코드 핫 리로드는 제공하지 않는다.

## 검증

- 준비 중 현재 포인터 유지, 중복 확인, 준비본 고정, 해시/시작 검사/디스크 오류, 준비본 재사용·손상 거절, 최종 확인 없는 종료 거절, 저장 변화 시 롤백 거부, 인증된 고정 IPC 명령을 검사한다.
- Qt에서 알림 보류, 연속 적용, 초기/최종 저장 실패, 종료 확인 실패, 가챠 연출 정리, Drive 실패 표식과 저장 유지, 일반/개발자 모드 전달을 검사한다.
- 격리된 실제 두 게임 프로세스에서 준비→저장→정원 잠금 해제→종료 확인→활성화→새 프로세스 실행→동일 골드 복원을 검사한다.
- 배포의 `--verify-bundle`은 EXE와 Python-BAT 각각 실제 패키지에 이 경로를 실행한다. 주입한 합성 ‘다음 버전’ 메타데이터와 동일 패키지로 검증하며, 실제 GitHub에 후속 Release를 게시한 인간 PC 실기라고 주장하지 않는다.
- 320/520px 알림 화면을 렌더 검수했다. 실제 사용자 PC의 장시간 플레이·다양한 네트워크·DPI 검수는 별도다.
