# 식물별 화분 꾸미기 — 이슈 #26

[이슈 #26](https://github.com/badbed7/morning-bloom/issues/26)과 [추가 UI 의견](https://github.com/badbed7/morning-bloom/issues/26#issuecomment-6649839684)을 반영한다.

## 사용 흐름

1. 정원에서 꾸밀 식물을 클릭한다. 같은 품종이 여러 송이면 `장미 1`, `장미 2`처럼 표시한다.
2. 보유 화분이 먼저 나오는 목록에서 화분 종류를 고르고 색상을 고른다. 미보유 화분은 흑백이며 적용할 수 없다.
3. 미리보기에서 모양·무늬·색을 확인하고 `이 화분에 담기`를 누른다. 선택 시 식물이 살짝 떠올랐다 내려오는 짧은 연출을 제공한다.
4. `취소`하거나 창을 닫으면 기존 설정을 유지한다.

화분 화면의 `화분 꾸미기`에서는 빈 슬롯이나 재배 중인 식물을 같은 화면으로 꾸민다. 심기 전에도 선택할 수 있다. 빈 슬롯 외형을 적용해도 씨앗을 소비하지 않는다. 재배 중에는 실제 성장 단계로 미리보기를 표시한다.

색상은 기본·베이지·차콜·버건디·아이보리·세이지·더스티 블루다. 종류를 유지하면서 색만 바꿀 수 있고 같은 종류의 화분을 여러 식물에 다른 색으로 적용할 수 있다. 품종별 기본 토분 색상 지정은 장미 8색 개발에서 철회했다. 사용자가 선택한 종류·색상은 유지하며 장미 꽃잎 색은 별도 품종 ID로 결정한다. [장미 8색 설계](rose-varieties.ko.md).

햇빛 클릭은 기존 수집 동작을, 드래그는 판매 동작을 유지한다. 우클릭은 기존 플로팅·복귀 메뉴를 연다.

## 저장과 렌더링

- 품종이 아닌 식물 ID로 설정한다. 장미 한 송이의 변경이 다른 장미에 전파되지 않는다.
- 재배 슬롯의 `pot_skins`, `pot_colors`를 수확 시 같은 식물 ID의 `flower_pots`로 옮긴다. 판매 시 해당 ID의 설정만 제거한다.
- 정원·드래그 미리보기·보관 꽃 목록·플로팅·분무 화면에서 같은 외형을 그린다. 상점의 공통 기본 화분을 바꿔도 이미 수확한 식물의 개별 설정은 유지한다.
- 적용은 기존 저장 트랜잭션을 사용한다. 저장 실패 시 원래 설정으로 되돌리고 선택 창을 유지한다. 적용 직전에 사라진 식물에는 설정을 쓰지 않는다.
- 저장 v19는 v18의 슬롯별 종류와 모든 식물 ID·성장·경제 데이터를 보존한다. 색상은 `original`, 기존 정원 꽃은 이전의 공통 기본 종류로 초기화한다. v1~v17도 기존 이전 경로를 거쳐 같은 형식으로 이전한다.
- 로컬 이전 시 기존 파일 원문을 `.v18-migration.bak` 등 버전별 백업에 보존한다. 클라우드 복원도 같은 검증·이전 경로를 사용한다. 미래 버전과 손상 데이터는 덮어쓰지 않는다.

## 검증 범위

`python/tests/test_plant_pots.py`에서 동일 품종 개체 독립성, 같은 종류·다른 색상, 취소·저장 실패 복구, 미보유·잘못된 색상·삭제된 ID 거부, 클릭과 햇빛·판매 드래그 구분, 성장 보존과 수확 후 설정 유지, 재실행·클라우드 복원, 이전 파일 원문 보존, 공통 렌더링, 꽃잎 색 보존, 320px·520px 선택 창 레이아웃을 검증한다. 기존 저장·클라우드·UI 회귀 테스트를 포함해 Python 275개 중 274개 통과·선택 환경 테스트 1개 건너뜀, 런처·패키징 44개 통과를 확인했다.

Qt offscreen에서 320px·520px 선택 화면을 렌더링해 미리보기·목록·적용 버튼과 스크롤을 확인했다. Windows 네이티브 창 동작은 GitHub Actions와 별도 실기기 점검의 범위를 따른다.
