## 클라우드 동시 저장 설계

Drive v3의 덮어쓰기 요청에 대한 서버 원자적 조건부 갱신을 가정하지 않는다. 각 백업을 독립적인 완전한 스냅샷으로 생성하고 이전 버전 ID를 private appProperties와 저장 envelope에 기록한다. 새 백업은 이전 파일을 수정·삭제하지 않는다.

조회 후 다른 PC의 변경이 확인되면 업로드를 거부하고 다시 확인한다. 같은 부모를 읽은 두 PC가 동시에 생성한 경우에는 두 백업이 모두 남는다. 다음 조회에서 서로 다른 말단 버전을 충돌로 인식하고 사용자가 선택한 정원으로 두 버전을 연결하는 새 백업을 생성한다. 과거 파일은 그대로 보존한다. 여러 말단이 동일한 진행이면 자동으로 합친다. 과거 백업은 용량을 사용하며 보관 개수 제한·자동 삭제는 이번 범위에 포함하지 않는다.

새 스냅샷은 v2 파일명으로 생성하여 구버전 클라이언트의 v1 덮어쓰기 조회와 분리한다. v1도 함께 읽되 파일 ID와 Drive version을 합친 식별자로 이전 관계를 기록한다. 이전 PC가 v1을 다시 수정하면 새 v2를 훼손하지 않고 별도 충돌로 감지한다.

최초 생성은 metadata와 저장 내용을 multipart 요청 하나로 전송한다. 과거 버전에서 생성만 된 size=0 legacy 파일은 건너뛰되, 비어 있지 않은 손상 파일이나 미래 저장 형식은 쓰기를 막아 보존한다. 인증 오류는 기존 재연결 분기를 사용한다. 백업 원문·토큰·secret을 로그에 출력하지 않는다.

참고: [앱 데이터 저장](https://developers.google.com/workspace/drive/api/guides/appdata), [multipart 업로드](https://developers.google.com/workspace/drive/api/guides/manage-uploads), [파일 메타데이터](https://developers.google.com/workspace/drive/api/reference/rest/v3/files).

## 검증

- 기존 전체 회귀 검사 및 새 Qt 흐름 검사.
- 실제 로컬 HTTP 서버에서 완전한 최초 생성, 최초 실패 후 재시도, 성공 응답 유실 복구, 오래된 조회로 쓰기 거부, 두 PC 동시 생성과 충돌 해소, legacy 저장 이전, 빈 파일 처리, 손상/미래 저장 보호.
- 320/520px Qt 렌더 검수. 화면 크기를 반복 변경해도 카드가 겹치지 않고 스크롤·하단 버튼을 사용할 수 있는지 검사.
- 게임 EXE와 BAT payload의 game_entry에서 실제 클라우드 HTTP 전송 함수를 사용하여 누락된 중간 인증서 조회, 정상 체인 성공, 미신뢰/만료/호스트 불일치 거부를 Windows 빌드에서 검사.
- Windows 빌드·패키지 실행 검사와 공개 EXE/BAT 업데이트 feed 검사는 기존 릴리즈 workflow에서 실행한다.

이번 작업은 격리된 임시 저장과 로컬 인증서/HTTP 서버를 사용한다. 실제 사용자 Google 계정 로그인·OAuth 토큰·Drive 백업을 읽거나 변경하지 않았다. 실제 계정의 인증·정책·권한 문제 추적은 #8의 잔여 확인 항목과 구분한다.
