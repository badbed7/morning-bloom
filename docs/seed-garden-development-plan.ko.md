# Morning Bloom 게임 반영 개발 기획안

버전 1.0 · 2026-10-15 · 구현 착수용 초안

대상: Windows / Python 3.12 / PySide6 기반 Morning Bloom. 기준 코드: `badbed7/morning-bloom`, `0fdda3093b9ac7a31d77a8286dd3eac54b8c4fb1`.

목표는 기존 잠금 도감을 실제 획득·재배·꾸미기·효과·저장으로 연결하고, 씨앗·정원·화분을 얻는 보드형 가챠를 제공하는 것이다. 이 문서는 개발 명세이며 게임 구현이나 배포 완료 보고가 아니다.

## 1. 개발 목표와 결정 수준

### 1.1 사용자 요청으로 정해진 방향

- 꽃·식물, 정원, 화분의 등급은 S / A / B / C로 표기한다.
- 모든 정원과 화분은 각자 다른 효과를 갖는다.
- 이전 신규 식물 시안 8종을 포함한다.
- 주 5회 뽑기를 경제 설계의 기준으로 삼는다.
- 보드 중앙에 씨앗·정원·화분을 표시하고 랜덤으로 획득한다.
- 보드 양옆의 특정 지점 2곳에 도착하면 A~S급 전용 스페셜 보드로 들어간다.

### 1.2 이 개발안에서 구체화한 제안

20칸 일반 보드, 6칸 스페셜 보드, 무료 스페셜 1회, 세부 확률, 주간 지급 방식, 꽃잎 교환 가격, 신규 식물 재배 수치, 효과 상한과 장착 규칙은 구현을 위한 제안값이다. 사용자의 확정 지시와 구분해 관리한다. 개발자 정원에서 구현·검증할 수 있는 기본값으로 제공하며, 실제 배포 전 경제 검수에서 조정할 수 있다.

### 1.3 이번 완성 범위

| 시스템 | 완성 범위 |
|---|---|
| 꽃·식물 | 기존 14종 + 신규 8종, 총 22종 등급 표시와 재배 |
| 정원 | 기존 4종 + 신규 79종, 총 83종 적용과 개별 효과 |
| 화분 | 기존 4종 + 신규 41종, 총 45종 적용과 개별 효과 |
| 보드 보상 | 씨앗 20종 + 정원 79종 + 화분 41종, 총 140종 |
| 가챠 | 일반 이동, 좌우 스페셜 입장, 무료 보상, 결과·중복·이력 |
| 경제 | 주간 주사위 5개, 이월, 공통 꽃잎, 미해금 항목 선택 교환 |
| 저장 | v13→v14 이전 제안, 기존 재배·소유권·배치·클라우드 보존 |
| 배포 | Python-BAT와 Windows EXE에 동일 데이터·그림 포함 |

다섯·여섯 번째 재배 화분, 결제, 별도 게임 서버, 꽃꽂이·교배는 이번 구현 범위에 추가하지 않는다.

## 3. 콘텐츠와 등급 정의

### 3.1 전체 목록과 실제 보상 풀

| 분류 | 전체 S/A/B/C | 전체 수 | 보드 S/A/B/C | 보드 수 |
|---|---|---:|---|---:|
| 꽃·식물 | 4 / 8 / 6 / 4 | 22 | 3 / 7 / 6 / 4 | 20 |
| 정원 | 7 / 18 / 30 / 28 | 83 | 7 / 18 / 30 / 24 | 79 |
| 화분 | 4 / 8 / 13 / 20 | 45 | 4 / 8 / 13 / 16 | 41 |
| 합계 | 15 / 34 / 49 / 52 | 150 | 14 / 33 / 49 / 44 | 140 |

- 고대 꽃은 기존 랜덤 씨앗 0.1%, 민들레는 홀씨놀이 보상을 유지하며 보드 씨앗 풀에서 제외한다.
- 기존 정원 4종과 화분 4종은 기존 지급·햇빛 구매 경로를 유지하며 신규 보드 풀에서 제외한다.
- 기존에 구매 가능한 꽃 12종은 등급을 붙여도 구매 권한을 회수하지 않는다.
- 한 번 소유한 꾸미기 외형은 모든 재배 슬롯에 반복 장착할 수 있다. 스킨을 소모하지 않는다.
- 등급은 외형 희소성·획득 난도·재배 역할을 나타낸다. S가 모든 품종에서 가장 빠른 골드 생산을 보장하는 구조로 만들지 않는다.

### 3.2 식별자

표시 이름으로 저장하거나 이름 비교로 보상을 지급하지 않는다.

- 기존 꽃은 `daisy`, `starflower`, `tulip` 등 실제 종 ID를 유지한다.
- 신규 식물은 기존 `catalog_plant_000`~`catalog_plant_007`을 재배 종 ID로 연결한다.
- 신규 정원은 `catalog_garden_001`~`catalog_garden_079`, 신규 화분은 `catalog_pot_004`~`catalog_pot_044`를 유지한다.
- 기본 정원 `grass`와 기존 정원 `cream`, `sky`, `lavender`, 기존 화분 `terracotta`, `ivory`, `sage`, `rose`를 유지한다.
- 다른 분류에서 같은 ID가 있을 수 있으므로 전역 키는 `(category, item_id)`다. 예: 식물 `lavender`와 정원 `lavender`.
- 이 문서의 F-/G-/P- 번호는 기획·효과 식별용이다. 기존 저장 ID를 대체하지 않는다.

## 4. 일반 보드 명세

### 4.1 배치

7열×5행의 외곽 20칸을 시계 방향으로 돈다. 가운데 5열×3행에 씨앗·정원·화분 아이콘을 표시한다. 중앙 아이콘은 보상 종류와 보유 목록으로 연결되며 다음 결과를 선택하는 기능은 갖지 않는다.

| 칸 번호 | 종류 |
|---|---|
| 0, 3, 6, 10, 13, 16 | 씨앗 |
| 1, 4, 7, 11, 14, 17 | 정원 |
| 2, 5, 9, 12, 15, 19 | 화분 |
| 8 | 오른쪽 스페셜 입구 |
| 18 | 왼쪽 스페셜 입구 |

신규 시작 위치는 0번이며 시작 보상은 없다. 주사위는 정수 1~6 각각 1/6이고 `도착=(현재 위치+주사위)%20`이다. 통과 칸 보상은 없으며 입구에 정확히 멈출 때만 스페셜로 이동한다.

### 4.2 일반 보상 추첨 순서

1. 일반 주사위 1개 사용 가능 여부를 확인한다.
2. 주사위 값으로 실제 최종 도착 칸을 계산한다.
3. 일반 칸이면 그 칸의 분류를 정하고 등급을 정수 티켓 9장으로 추첨한다: C 5장 / B 3장 / A 1장.
4. 해당 분류·등급의 고정 버전 보상 풀에서 품목 1개를 균등 추첨한다.
5. 중복·해금·꽃잎 보상을 포함한 거래 결과를 확정 저장한 뒤 이동·결과 연출을 한다.

일반 보상 칸 자체에서는 S가 나오지 않는다. 실제 도착 종류와 무관하게 미리 독립 50/30/15/5 결과를 뽑고 보드 이동을 끼워 맞추지 않는다.

## 5. 스페셜 보드 명세

좌우 입구는 같은 스페셜 보드를 사용한다. 입구 칸에서 일반 보상을 추가 지급하지 않는다.

| 무료 주사위 | 도착 보상 | 확률 |
|---:|---|---:|
| 1 | A 씨앗 | 1/6 |
| 2 | A 정원 | 1/6 |
| 3 | A 화분 | 1/6 |
| 4 | S 씨앗 | 1/6 |
| 5 | S 정원 | 1/6 |
| 6 | S 화분 | 1/6 |

일반 보드에서 입구로 도착하는 거래를 확정할 때 무료 주사위 값·품목도 함께 확정해 `pending_special`에 저장한다. 사용자는 무료 버튼을 눌러 결과를 공개한다. 종료·재실행·앱 전환으로 다시 추첨하지 않는다.

- 일반 주사위 1개를 쓰고 입구에 도착하면 무료 스페셜 1회를 얻는다.
- 스페셜에서 A 또는 S 1개를 받고 같은 입구 칸으로 복귀한다.
- 무료 회차는 일반 주사위 수량과 일반 누적 회수를 늘리거나 줄이지 않는다.
- 스페셜 안에는 추가 주사위·다른 입구를 두지 않는다.
- 일반 보드 마지막 주사위로 입장해도 무료 회차는 사용할 수 있다.
- 무료 회차 대기 중에는 다음 일반 회차를 진행할 수 없다.
- 일반 주사위 5회로 최종 아이템 5개를 얻는다. 입구 회차의 보상이 무료 스페셜 결과로 완성되는 구조다.

## 6. 확률과 경제 기본값

### 6.1 보드 확률 검증값

장기 균등 위치에서 입구 도착률은 2/20=10%다. 스페셜에서 A/S가 각각 50%이므로 보드 보상 전체는 C 50% / B 30% / A 15% / S 5%가 된다. 분류는 각각 장기 평균 1/3이다.

| 지표 | 값 |
|---|---|
| 스페셜 입장 평균 간격 | 일반 10회, 주 5회면 약 2주 |
| S 보상 평균 간격 | 일반 20회, 주 5회면 약 4주 |
| 신규 시작 첫 20회 스페셜 기대값 | 약 1.934657회 |
| 신규 시작 첫 20회 S 기대값 | 약 0.967328개 |
| 신규 시작 첫 20회 S 1개 이상 확률 | 약 64.9122% |

평균은 보장 주기가 아니다. 다음 회차 확률은 현재 위치에 따라 달라진다. UI에서는 일반 칸 내부 확률·입구 도착 조건·스페셜 확률·장기 평균을 분리해 안내한다.

### 6.2 주간 주사위 지급 제안

| 항목 | v1 제안값 |
|---|---|
| 기준 시각 | 매주 월요일 00:00, Asia/Seoul |
| 지급 | 해당 주 첫 접속에 일반 주사위 5개 자동 지급 |
| 이월 | 보유 주사위 이월, v1 보유 상한 없음 |
| 미접속 주간 | 과거 주간을 소급 지급하지 않음 |
| 첫 진입 | 그 주 5개를 1회 지급, 별도 첫 진입 추가 5개는 없음 |
| 구매 | v1은 골드·햇빛·현금 구매를 제공하지 않음 |
| 일반/개발자 정원 | 각각 독립된 지급 기록과 잔액 |

지급 ID는 해당 주 월요일의 한국 날짜를 사용한다. 마지막 지급 주간과 관측 시각의 상한을 저장하고 시계 역행 시 과거 주간을 다시 지급하지 않는다. 로컬 저장 게임이므로 파일 전체 되돌리기나 여러 PC의 독립 진행까지 서버 권한으로 막는 설계는 아니다.

### 6.3 보상·중복·선택 교환 제안

보드 보상 1개가 확정될 때 공통 꽃잎 1개를 기본 지급한다. 입구 도착 직후에는 지급하지 않고 스페셜 결과 확정 시 지급한다.

| 상황 | 지급 |
|---|---|
| 신규 식물 품종 | 씨앗 구매 권한 영구 해금 + 씨앗 1개 + 기본 꽃잎 1개 |
| 이미 해금된 품종 | 씨앗 1개 + 기본 꽃잎 1개 + 등급별 중복 꽃잎 |
| 미보유 정원·화분 | 영구 소유권 + 기본 꽃잎 1개 |
| 보유 정원·화분 | 기본 꽃잎 1개 + 등급별 중복 꽃잎 |

| 등급 | 추가 중복 꽃잎 | 미해금 항목 선택 교환 가격 |
|---|---:|---:|
| C | 1 | 3 |
| B | 2 | 8 |
| A | 5 | 20 |
| S | 10 | 40 |

선택 교환 대상은 보드 풀의 미해금 품종·미보유 정원·미보유 화분이다. 이미 소유한 항목을 다시 교환해 꽃잎을 돌려받는 거래는 허용하지 않는다. 품종 교환은 해금과 씨앗 1개를 함께 주며, 기본·중복 꽃잎을 다시 지급하지 않는다.

중복이 하나도 없어도 보상 40개를 완료하면 원하는 S 한 종류를 선택할 수 있다. 주 5회 기준 8주이며 중복이 있으면 빨라진다. 교환 보상은 앞 절의 보드 등급 확률 5%에 포함하지 않는다. v1은 별도의 확률 상승·S 천장을 추가하지 않는 초안이며, 선택 교환을 목표 획득 경로로 사용한다.

## 7. 신규 식물 8종의 재배 수치 제안

## 8. 정원·화분 효과 적용 규칙

### 8.1 장착과 효과 고정

정원은 전체 선택 1개, 화분 외형은 재배 슬롯별 1개다. 첫 물주기 때 선택한 정원·화분의 효과 버전과 수치를 재배 개체에 저장한다. 재배 중 외형 변경은 가능하며 변경 화면에서 현재 재배의 효과와 다음 재배의 효과를 구분해 안내한다.

이미 재배 중인 v13 식물은 수확까지 기존 규칙을 유지한다. 첫 물 이전을 포함해 기존 개체에 새 능력을 소급 부여하지 않는다. 이전 후 새로 심고 첫 물주기를 한 개체부터 적용한다. 튜토리얼에는 성장·직접 단축 효과를 적용하지 않는다.

정원에 이미 보관한 꽃의 햇빛 효과는 현재 선택한 정원을 생산 주기 시작 시 고정한다. 진행 중인 주기와 이미 생긴 햇빛은 외형 변경으로 재계산하지 않는다.

### 8.2 상한과 계산

| 계열 | 상한·계산 제안 |
|---|---|
| 성장 속도 | 정원+화분 합산 +20%, 합산 후 한 번 적용 |
| 물·분무 대기 | 각 기본 대기 대비 최대 20% 감소 |
| 장비 판매가 | 기본 판매가 기준 합산 +25%, 기존 첫 분무 보너스와 가산 |
| 햇빛 생산 주기 | 최대 15% 감소, 최소 17분 |
| 신규 효과의 직접 성장 단축 | 개체 기본 성장 시간의 10%까지 |
| 비료로 적립한 성장량 | 기본 성장의 25%, 시멘트만 26% |
| 비료 재고 | 5개, 효과 지급 보류분은 별도 기록 |

성장 속도 10%와 8%는 18%로 더한다. 기본 시간이 T이면 해당 조건을 계속 유지했을 때 자연 성장 완료 시간은 T/1.18이다. 판매가 보너스 15%와 12%는 25%로 제한한다. 기존 첫 분무 10%에 추가 15%p가 붙으면 해당 성분은 25%이며, 장비가 추가한 15%p는 장비 판매 상한에 포함한다.

골드 보너스 소수는 1/10000G 정수 단위로 누적해 저장하고, 1G 이상이 되면 같은 거래에서 지갑에 지급한다. 비율은 정수 basis point로 정의한다. 경과 시간은 기존 유한 실수 초를 유지하되 수치 오차 허용 범위를 검증한다.

직접 단축 10%에는 새 장비가 추가한 단축분만 적립한다. 기존 물 180초·분무 60초·비료 600초의 기본 적립은 제외하고 증폭으로 추가된 초와 단계 보너스 등은 포함한다. 비료 무료 사용은 소비 비용만 면제하므로 기본 600초를 장비 추가분으로 다시 세지 않는다. 비료 전체 적립량은 별도로 25%/26%에 포함한다. 실제 적립은 남은 성장량·비료 잔여 한도·신규 추가분 한도를 함께 고려해 제한한다. 효과를 줄 수 없는 경우 재고를 소모하지 않으며 비료 잔여 한도만큼 부분 적립한 경우에는 정상 사용 1회로 센다.

### 8.3 공통 효과 엔진

128개 품목마다 UI·모델에 독립 분기를 추가하지 않는다. 다음 계열을 조합하고 품목마다 대상·조건·보상을 명시한다.

| 계열 | 필요한 연산 |
|---|---|
| 재배 수정 | 성장 배율, 품종·색상·단계·진행 비율 조건 |
| 돌봄 수정 | 대기 감소, 직접 성장, 횟수·순서·시간 창 |
| 경제 보상 | 판매가, 골드 환급, 첫 수확·품종 연속 기록 |
| 비료 | 효율, 누적 단축 상한, 무료 소비, 지급 보류 |
| 정원 구성 | 전시 수·품종 수·스킨 수 조건, 조건 충족 성장량 |
| 햇빛 | 꽃별 주기, 미수집 상한, 생산·수집 추가 보상 |
| 미니게임 | 분무 클릭 수·간격, 비료 첫 라운드 구간, 고리 보상 |
| 오프라인 | 종료 중 성장, 복귀 1회 효과, 오프라인 개화 여부 |

정의 필드 예: `effect_id`, `version`, `scope`, `event`, `conditions`, `operations`, `per_crop_limit`, `cooldown`, `cap_group`, `priority`. 지원하지 않는 연산은 0 효과로 무시하지 않고 콘텐츠 검증에서 오류 처리한다.

### 8.4 조건 판정의 구체화

- 추가 물주기 횟수는 현재 코드의 `water_count`에서 첫 물주기 1회를 뺀 값이다.
- ‘성장의 절반 이상 유지’는 조건을 만족하며 적립한 자연 성장량이 기본 성장 시간의 50% 이상인 경우다. 돌봄·비료의 직접 단축은 자격 성장량에 포함하지 않는다.
- 동시 재배는 첫 물을 준 성장 중 개체만 센다. 빈 화분·미급수·성숙 완료 개체는 제외한다.
- 꽃 색상은 정의의 `color_tags`로 관리한다. 기존 분홍: 장미·튤립·코스모스, 흰색: 데이지·은방울꽃, 보라: 라벤더·팬지. 신규 잎 식물에는 별도 잎 태그를 붙이고 꽃 색상 조건에 자동 포함하지 않는다.
- 일일 비료 효과는 마지막 성공 지급으로부터 24시간 기준이다. 지급 권리를 여러 개 무제한 적립하지 않고 미지급 1개까지 보관한다.
- 단계 경계 보상은 개체·효과·경계 번호별 1회다. 직접 단축으로 여러 경계를 넘으면 각 경계를 순서대로 처리하되 중복 적용하지 않는다.
- 실제 추가 보상을 받은 이벤트는 원래 이벤트 카운터에 다시 넣지 않는다. 햇빛 10개 수집 추가분이나 고리 골드 추가분이 연쇄 보상을 만들지 않는다.
- 판매 자격은 성숙 시점까지 추적한다. ‘최초 수확’처럼 전역 기록이 필요한 조건은 실제 수확 거래에서 한 번 판정한다.

### 8.5 오프라인 계산과 시간 경계

현재 `advance(now)`는 실행 중 갱신과 종료 중 경과를 구분하지 않는다. 신규 계산에서는 `ONLINE`, `OFFLINE_RESUME`, `DEMO_ADVANCE` 문맥을 명시한다. 경과 시간이 길다는 이유만으로 오프라인 보너스를 주지 않는다. 최소화와 가챠 창 열기는 온라인 진행이다.

계산 구간은 성장 단계, 조건 진입·종료, 성숙, 개체별 오프라인 상한 등 다음 경계에서 나눈다. 여러 재배 개체의 동시 조건이 달라지면 공통 시간 경계에서 다시 계산한다. 큰 경과를 한 번 적립한 결과와 동일 구간을 나누어 적립한 결과가 일치해야 한다.

부팅·실행 재개 시 이전 세션 마지막 체크포인트 이후를 오프라인으로 처리한다. 종료 마커를 함께 남기되 비정상 종료는 마지막 정상 체크포인트부터 계산한다. 정상 자동 저장 간격에 따른 온라인/오프라인 추정 오차는 최대 기존 저장 간격 30초로 허용하고 명세에 기록한다. 개발자 +6시간은 기본적으로 `DEMO_ADVANCE`이며 오프라인 전용 효과는 별도 테스트에서 검증한다.

## 9. 화분 슬롯·수확·외형 처리

현재 재배 딕셔너리 `pots`는 수확 시 초기화된다. 장착과 품종 연속 기록은 별도 `pot_slots`에 둔다.

```text
pot_slots[i]
  slot_id                 # 구매한 재배 슬롯의 안정 ID
  equipped_skin_id        # 다음 재배에 사용할 스킨
  previous_harvest_species
  terrazzo_sequence       # 해당 스킨을 사용한 연속 품종 묶음

pots[i]
  기존 재배 필드
  effects_snapshot        # 첫 물주기 시 고정한 정의·버전·수치
  effect_progress         # 횟수·순서·단계 경계·자격 성장량
  fertilizer_growth_seconds_used
  reward_flags
```

v13의 공용 스킨은 모든 기존 슬롯의 초기 스킨으로 복사한다. 빈 화분에서도 장착을 바꿀 수 있고, 수확해도 슬롯 장착은 유지한다. 정원에 보관된 꽃은 수확 당시 외형과 효과 출처를 보존하며, 기존 보관 꽃은 이전 시점 공용 스킨을 복사한다. 보관 꽃의 외형 변경은 해당 꽃에 별도로 적용하는 동작으로 정의하고 슬롯의 다음 장착과 혼동하지 않는다.

`garden_view`, 수확 결과, 드래그 그림, 바탕화면 창이 같은 외형 해석 함수를 사용한다. 플로팅으로 이동해도 같은 식물 ID·햇빛 ID를 사용하며 보상 생산 개체가 복제되지 않는다.

## 10. 저장 데이터 설계

기준 코드에서 출발한다면 저장 스키마 14를 제안한다. 실제 착수 시 다른 변경으로 번호가 사용되었다면 다음 번호를 사용한다. 저장 버전과 보드 콘텐츠 버전은 분리한다.

| 새 상태 | 주요 필드 |
|---|---|
| 콘텐츠·해금 | `unlocked_plants`, `content_version` |
| 주사위·교환 | `board_tickets`, `petals`, `weekly_grant_id`, `max_observed_time` |
| 보드 | `board_id`, `board_version`, `position`, `paid_roll_count`, `completed_reward_count` |
| 무료 스페셜 | `entry_position`, `origin_action_id`, `special_die`, `reward_plan`, `pool_version` |
| 거래 | `prepared_action`, `action_seq`, `last_committed_seq`, `unseen_result`, 제한된 보상 이력 |
| 장착·효과 | `pot_slots`, 개체 효과 스냅샷·횟수·사용량·지급 플래그 |
| 햇빛 | 꽃별 `production_elapsed`, `cycle_snapshot`, 최초 주기 처리 여부 |
| 공통 효과 기록 | 최초 수확 품종, 수집·고리 카운터, 지급 보류 비료, 소수 골드 누적 |

검증 조건: 음수 잔액 금지, bool을 int로 허용하지 않음, NaN/무한대 금지, 위치 0~19, 무료 보드 대기 위치는 8 또는 18, 등급·분류·품목 ID가 저장된 풀 버전과 일치, 슬롯 수와 재배 수 일치, 장착은 소유한 품목, 효과 중복 지급 플래그 일관성, 완료 보상 수≤일반 회수.

내부 정수 잔액에는 비정상 파일 방어용 범위 검증을 두되 사용자에게 임의 보유 한도 기능으로 표시하지 않는다. 보상 이력은 최근 200개를 보관하고, 거래 재처리 방지는 이력 보존 여부와 독립된 증가 순번으로 처리한다.

## 11. 거래·실패 복구·클라우드

### 11.1 저장 전 결과 공개 금지

`Window.act()`의 메모리 복원만으로는 재실행 후 같은 랜덤 결과 재시도를 보장하기 어렵다. 보드 거래는 준비 상태도 정원 저장에 포함하는 두 단계로 처리한다.

```text
READY
  → 입력 검증·경과 시간 정산
  → 주사위·품목·중복·보상 계획 생성
  → PREPARED 저장: 잔액은 아직 차감하지 않음, 계획은 고정
  → 계획 적용 + 잔액/위치/보상/완료 순번 원자적 저장
  → READY 또는 SPECIAL_PENDING
  → 이동·결과 연출

SPECIAL_PENDING
  → 저장된 무료 결과 계획 준비·확정
  → 무료 보상·기본 꽃잎·중복 꽃잎 원자적 저장
  → READY + 결과 표시
```

- 준비 저장 실패: 주사위·결과를 공개하지 않고 지갑·위치를 변경하지 않는다.
- 확정 저장 실패: 준비 상태를 유지하고 ‘저장 재시도’로 같은 결과를 확정한다. 다른 변경 행동은 잠근다.
- 재실행: 경과 시간 적립과 클라우드 자동 업로드보다 먼저 준비 거래를 복구한다. 저장된 계획을 재사용한다.
- 확정 후 연출 도중 종료: 저장된 결과를 다시 보여줄 수 있으나 재지급하지 않는다.
- UI 잠금 외에 모델의 거래 순번·멱등성 검증으로 빠른 클릭과 같은 요청 재전송을 막는다.
- 준비→확정 사이에는 돌봄·자동 저장·정원 전환 등 정원 쓰기 작업을 직렬화한다. 준비 실패 상태에서 정상 종료하면 준비 상태를 보존한다.

### 11.2 클라우드

현재 Google Drive의 전체 정원 스냅샷과 5분 자동 백업 흐름을 유지한다. 새 보드·주사위·꽃잎·준비 거래·해금·효과 상태도 같은 정원 스냅샷에 포함한다.

다른 PC와 충돌하면 기존처럼 기준 정원을 선택한다. 로컬과 클라우드의 주사위·꽃잎·해금을 합산하지 않는다. 고정된 무료 결과가 있는 저장을 복원하면 같은 결과로 이어진다. 미래 스키마는 보호하고, 복원 직전 `.pre-cloud.bak`를 유지한다. 명시적으로 더 오래된 정원 전체를 복원하면 진행 전체가 되돌아갈 수 있으며, 서버 없는 구조에서 이를 별도 전역 보상 원장으로 차단한다고 약속하지 않는다.

## 12. v13 저장 이전

1. 원본 `garden.json`을 별도 v13 이전 백업으로 보존한다. 검증 실패 시 원본을 쓰지 않는다.
2. 기존 v1~v12 이전을 거쳐 정규화된 v13을 만든 뒤 v13→v14를 한 번 적용한다.
3. 기존 꽃·골드·씨앗·햇빛·비료·재배 시간·개체 ID·정원 배치·데스크톱 배치를 그대로 보존한다.
4. 기존 구매 가능 꽃 12종을 `unlocked_plants`에 추가한다. 새 8종은 미해금, 씨앗 재고는 0이다.
5. 기존 정원·화분 소유권을 유지하고 공용 스킨을 슬롯과 기존 보관 꽃에 복사한다.
6. 기존 성장 중 개체는 새 장비 효과가 없는 이전 규칙 스냅샷을 받는다. 새 개체부터 효과를 적용한다.
7. 보드는 위치 0, 일반 회수·완료 보상 0, 꽃잎 0으로 시작한다. 주사위는 주간 지급 서비스를 통해 한 번만 5개를 받는다.
8. 기존 공통 햇빛 `sun_elapsed`를 기존 보관 꽃의 첫 개별 주기에 복사하고, 첫 주기는 기존 20분으로 유지한다. 다음 주기부터 새 정원 효과를 반영한다. 기존 햇빛 토큰은 보존한다.
9. 새 필드까지 검증한 결과를 원자적으로 저장한다. 다시 불러와도 이전·주간 지급을 반복하지 않는다.

주의할 실제 코드 구조: 기존 이전 함수 중 `Garden(0).to_dict()`와 현재 `Garden.from_dict()`로 과거 버전을 검증하는 부분이 있다. 새 필드를 현재 모델에 추가하면 과거 필드 집합 검증이 깨질 수 있으므로 과거 스키마 정의·검증을 고정 데이터로 분리하고 마지막 단계에서만 현재 모델로 변환한다.

비료는 기존 횟수와 별도로 실제 단축 초 누적을 저장한다. 이전 개체는 기존 사용 횟수×600초를 기준으로 보존하고 기존 상한을 유지한다. 새 규칙 개체는 실제 적립 성장량으로 25%/26%를 검사한다. 무료 비료도 사용 횟수와 단축량에 포함한다.

보드는 재배 창을 강제로 키우지 않는 별도 확장 창으로 만들고 720×560 논리 픽셀을 시작안으로 검수한다. 화면보다 크면 사용 가능한 작업 영역에 맞춘다. 기본 320·384·520px 재배 창은 기존 레이아웃을 유지하며 등급·장착 정보는 도움말이나 목록에서 펼쳐 본다.

보드 창은 본체의 불투명도·항상 위 설정을 따르고 드래그 이동·닫기·Esc를 지원한다. 이동·결과 연출 중에는 추가 입력을 잠그며 연출 건너뛰기는 저장된 결과만 바로 보여준다. 본체 최소화 시 보드도 함께 숨기고, 닫기는 보드만 닫아 재배와 플로팅 꽃을 유지한다. 종료·개발자 모드 전환·클라우드 복원 때 열린 창의 정원 참조를 해제한다.

랜덤 씨앗은 기존처럼 개화 전 구체 품종·상세 시간·판매가를 숨긴다. 등급 배지와 장비 적용 설명도 고대 꽃 정체를 미리 노출하지 않도록 ‘미확인 씨앗’ 상태에서는 품종 등급을 표시하지 않는다.

기존 `python/tests`와 `release/tests`를 유지하고 의미 있는 도메인·저장·화면 회귀를 추가한다. 테스트는 사용자 지갑을 사용하는 일반 저장과 분리한다. 파일 경로·필드만 그대로 비교하는 검증보다 실제 실패·재시작·조건 경계 시나리오를 우선한다.

## 17. 확률·경제 검증 방법

20개 위치의 전이 행렬에서 다음 위치 각각을 1/6로 계산한다. 입구의 경우 S 비율 1/2를 적용해 S 미획득 상태 확률을 누적한다. 독립 5% 가정으로 첫 20회 결과를 대체하지 않는다.

보드 1회마다 보상 1개가 완성되는 경우 장기 일반/특수 비중 90/10과 C/B/A/S 50/30/15/5를 확인한다. 유한 시작 구간은 6.1절의 정확 계산과 비교한다. 몬테카를로는 오류 탐지용 보조 검증으로 쓰고 범위·표본 수·시드를 기록한다.

경제 시뮬레이션에는 기존 구매 품종 12종을 이미 해금한 계정을 포함한다. 기본 꽃잎, 등급별 중복 꽃잎, 선택 교환을 모두 계산한다. 결과 항목은 미보유 획득 수, 종류별 완성률, 첫 S·목표 S까지의 회수, 꽃잎 잔액, 실제 골드/시간, 반복 돌봄 수다.

128효과의 조합을 모두 무조건 UI 실행하는 대신 품종·성장 시간·오프라인·비료·판매·햇빛 상한의 등가 클래스로 검증하고, 최대 이득 조합과 고정 보상 반복 조합은 별도 확인한다. 저가 꽃 +1G, 데이지 수확 햇빛, 분수대 비료, 핸들 스톤 무료 비료, 테라조 연속 수확을 우선 검사한다.

## 18. 그림·패키징·출시 기준

### 18.1 아트 작업

- 기존 시트의 이름·가격·테두리가 포함된 미리보기는 실제 재배·전시용 자산으로 직접 사용하지 않는다.
- 신규 식물은 품종당 5단계, 총 40개 상태와 씨앗·도감 아이콘을 준비한다. PNG 투명 자산 또는 기존 QPainter 확장 중 프로젝트 스타일에 맞게 택하고 혼용 시 렌더러로 통합한다.
- 정원 79종은 `tile`, `scene`, 기존 `gradient` 중 표시 방식을 지정한다. 타일 경계 반복, 확대 축소, 화면 비율과 꽃 가독성을 검사한다.
- 화분 41종은 몸체·테두리·앞면 마스크와 꽃의 기준점을 정의해 꽃마다 높이·겹침이 달라지지 않도록 한다.
- 각 콘텐츠에는 `preview_ready`, `render_ready`, `effect_ready`, 신규 식물은 `growth_ready`를 기록한다. 잠금 그림만 있는 항목을 실제 보상으로 열지 않는다.

### 18.2 빌드·호환

소스 직접 실행, Python-BAT 설치본, Windows EXE가 같은 콘텐츠·효과 버전을 사용해야 한다. Python 배포는 현재 소스·이미지 일부만 복사하므로 새 JSON·PNG 디렉터리 누락을 검증한다. EXE의 `--add-data`와 자산 경로 해석도 함께 갱신한다.

CI는 현재 Windows/Python 3.12의 두 unittest 묶음을 이어 쓰고 신규 보드·이전·효과 검증을 포함한다. 후보 패키지는 Python이 없는 환경의 EXE 실행, BAT 신규 설치·기존 설치 업데이트, 인터넷 없는 기존 설치 실행을 확인한다.

저장 스키마가 바뀌므로 구버전 실행 파일로 단순 되돌리는 배포를 하지 않는다. 문제 발생 시 보드 신규 거래를 잠근 수정 버전을 제공하고 현재 저장을 읽을 수 있게 한다. 이미 확정한 보상·소유권을 원격 설정 변경으로 삭제하지 않는다. 기존 정원의 명시적 백업 복구는 별도 사용자 복원 동작으로 다룬다.

### 18.3 최종 완료 기준

1. 보드로 얻은 씨앗을 심어 성숙·수확·판매할 수 있다.
2. 얻은 정원을 실제 배경으로 쓰고 모든 정원에 정의된 고유 효과가 있다.
3. 얻은 화분을 슬롯별로 장착하고 재배·정원·플로팅에서 같은 외형을 쓴다.
4. 좌우 입구에서 무료 A/S 보상을 받고 주사위 5회와 보상 5개의 관계가 유지된다.
5. 주간 지급·중복·교환·재실행·저장 실패·클라우드 복원에서 재화와 결과가 일관된다.
6. 기존 저장과 기존 꽃의 진행을 보존하고, 신규 효과는 정해진 적용 시점부터 동작한다.
7. 전체 150개 콘텐츠, 140개 보드 항목, 128개 정원·화분 효과의 정의·그림·검수 연결이 완성된다.
8. BAT·EXE 실제 후보 빌드 검수를 마치고 효과·경제 제안값의 배포 적용 버전을 기록한다.

## 19. 개발 산출물과 추적

이 문서와 함께 제공하는 `morning-bloom-content-handoff.json`에는 실제 기존 ID로 연결한 150개 품목, 보드 포함 여부, 등급, 효과 설명, 신규 재배 수치 제안과 출처를 담는다. 이 JSON은 개발 인계 목록이며 그대로 실행 엔진에 넣는 완성 설정 파일은 아니다. 효과 설명은 개발 시 명시적 연산과 조건으로 변환하고 검증해야 한다.

PR에는 D1~D9 단계, 관련 요구·검수 ID, 사용한 스키마·콘텐츠 버전, 실제 검증 결과를 기록한다. 본 문서에서 제안한 수치가 바뀌면 효과표·도감 안내·확률 안내·시뮬레이션 기준을 같은 변경에서 갱신한다.
