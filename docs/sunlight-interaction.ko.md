# 햇빛 수집·정원 꾸미기 기획

요청일: 2026-09-15. 기준: Python 2D 정원·순환 메뉴가 적용된 `main`.

상태: 햇빛 생성·클릭 수집 효과·배경 구매와 적용·v5 저장 이전·개발자 시간 이동을 구현했다. 후속 화분 스킨과 함께 Windows v0.4.0에 포함하며 공개 자동 업데이트 채널은 미연결 상태다.

## 1. 목표와 반복 흐름

일하는 동안 꽃을 키워 두고, 가끔 정원에 들러 톡톡 클릭하면 작은 보상을 받는다. 물주기처럼 반드시 해야 하는 일은 늘리지 않는다.

`꽃 재배 → 정원 보관 → 꽃에서 햇빛 생성 → 클릭 수집 → 꾸미기 구매·적용`

정원에 꽃을 남겨 두는 이유를 추가한다. 바로 팔면 골드를 얻고, 남겨 두면 햇빛과 전시의 즐거움을 얻는다. 화분 재배 시간·물주기·분무·판매가는 기존 규칙을 유지한다. 다른 게임의 수집 방식은 참고하되 그림·효과음·UI 자산은 자체 제작한다.

## 2. 재화 분리

| 재화 | 획득 | 사용 | 영향 |
| --- | --- | --- | --- |
| 골드 G | 꽃 판매 | 씨앗, 재배 화분 | 기존 재배 경제 |
| 햇빛 | 정원에서 생성된 빛 클릭 | 정원 배경 등 꾸미기 | 외형만 변경 |

햇빛으로 성장 가속·판매가 상승·필수 돌봄을 구매하지 않는다. 골드와 교환하거나 유료 결제를 붙이지 않는다. 꾸미기를 하지 않아도 기존 게임을 동일하게 즐길 수 있다.

## 3. 생성·수집 규칙

아래 시간·상한·가격을 첫 구현값으로 적용했다. 플레이 후 조정한다.

| 항목 | 초기 제안 |
| --- | --- |
| 생산 대상 | 정원에 보관한 개화 꽃. 재배 중인 꽃은 제외 |
| 생산 주기 | 정원 공통 시계로 20분마다, 현재 보관 꽃 1개당 햇빛 1개 |
| 클릭 보상 | 빛 하나당 햇빛 +1 |
| 대기 상한 | 정원 전체 9개. 이미 보유한 햇빛 재화에는 이 상한을 적용하지 않음 |
| 대기 수명 | 시간 만료 없음. 재접속 후에도 유지 |
| 첫 경험 | 최초 꽃 보관 시 햇빛 1개를 즉시 생성해 클릭을 안내. 저장 전체에서 한 번만 제공 |

- 최초 꽃 보관 시 공통 20분 시계를 시작한다. 꽃 추가·판매·화면 이동·햇빛 수집은 시계를 초기화하지 않는다.
- 매 회차 빈 대기 슬롯만큼만 생성한다. 초과분은 숨은 대기열로 쌓지 않는다. 꽃이 9개보다 많으면 생성 연출의 꽃 순번을 순환한다.
- 상한 상태에서도 회차는 경과한다. 수집 직후 과거 회차의 햇빛이 연달아 나오지 않고, 다음 정규 회차에 생산한다.
- 꽃이 하나도 없는 회차는 보상 없이 지나간다. 이후 다시 꽃을 보관해도 과거 빈 회차를 보상하지 않는다.
- 화분·상점·설정 화면을 보고 있어도 생산 시계는 흐른다. 수집은 정원에서만 한다. 정원 메뉴에 미수집 개수 표시를 검토한다.
- 앱 종료 중에도 경과한 회차를 계산하되, 현재 대기 상한 9개까지만 복귀 시 생성한다. 비워 둔 시간이 길다고 클릭할 빛 수백 개가 생기지 않는다.
- 휴가 모드에서는 생산 시계를 정지한다. 기존 햇빛 수집과 꾸미기 구매·변경은 가능하다.
- 이미 생성된 빛은 꽃 판매 후에도 남긴다. 빛은 꽃과 별개의 고유 ID를 가지며, 판매로 생성 주기나 지급 여부를 초기화하지 않는다.

경과 시간은 기존 게임 시계로 계산한다. 시간 역행은 보상을 만들지 않으며, 큰 시간 차도 회차마다 반복문을 돌리지 않고 상한까지 한 번에 계산한다. 꽃 수가 바뀌기 전에는 기존 꽃 수로 경과 회차를 먼저 정산한다.

## 4. 클릭 느낌과 드래그 충돌 방지

빛은 꽃 근처에서 작게 솟았다가 잔디 위에 머문다. 마우스를 올리면 크기와 테두리가 살짝 변한다. 클릭하면 약 0.35초 동안 작은 빛 조각이 퍼지고 `+1`이 떠오른 뒤 햇빛 잔액이 바뀐다. 생성·수집 소리는 기본 꺼짐으로 시작하고, 효과 줄이기 옵션에서는 입자와 튀는 움직임을 줄인다.

| 입력 | 처리 |
| --- | --- |
| 햇빛을 누르고 같은 햇빛 위에서 놓음 | 한 번 수집, 저장 성공 후 터지는 효과 |
| 햇빛을 누른 뒤 드래그 임계 거리 이상 이동 | 수집 취소. 꽃 드래그로 전환하지 않음 |
| 꽃·화분 영역에서 드래그 시작 | 기존 돈주머니 판매 흐름 유지 |
| 꽃을 끌고 햇빛 위로 이동 | 햇빛을 수집하지 않음 |
| 같은 빛 연속 클릭 | ID 확인으로 한 번만 지급 |
| 외부 드롭·우클릭·빈 곳 클릭 | 재화 변화 없음 |
| 수집 저장 실패 | 잔액과 빛을 복원, 오류 표시. 성공 효과는 재생하지 않음 |

햇빛은 메뉴·설정·판매 영역 위에는 배치하지 않는다. 꽃과 겹치면 햇빛을 먼저 판정하되 화분 하단은 드래그를 시작할 수 있도록 비워 둔다. 꽃이 많아 스크롤할 때도 대기 햇빛 개수와 ID는 유지한다. 위치가 화면 밖으로 나가면 정원 안의 빈 슬롯으로 재배치한다. 320px 창·고배율에서도 각각 누를 수 있는 클릭 영역을 확보한다.

## 5. 꾸미기 상점

기존 상점 안에 `재배 / 꾸미기` 분류를 둔다. 재배 상품은 G, 꾸미기 상품은 햇빛으로 가격과 잔액을 분명히 표시한다.

정원 배경과 화분 스킨을 아이콘으로 선택한다. 꽃이 식별되는 잔디 질감과 대비를 유지한다. 배경과 스킨은 외형만 변경하며 성장·판매가·돌봄 시계를 바꾸지 않는다.

| 배경 | 초기 가격 | 초기 소유 |
| --- | --- | --- |
| 기본 초록 잔디 | 무료 | 소유·적용 중 |
| 따뜻한 크림 정원 | 햇빛 12 | 미소유 |
| 맑은 하늘 정원 | 햇빛 24 | 미소유 |
| 저녁 라벤더 정원 | 햇빛 36 | 미소유 |

- 상품에서 배경 미리보기·가격·소유 상태를 확인한다. 미리보기만으로 잔액이나 적용 상태를 저장하지 않는다.
- `구매`하면 차감·소유권을 한 번에 저장한다. 구매만으로 현재 배경을 바꾸지 않는다.
- 소유한 상품에는 `적용`, 현재 배경에는 `사용 중`을 표시한다. 다시 적용하거나 기본 배경으로 돌아가는 것은 무료다.
- 잔액 부족·중복 구매를 차단한다. 저장 실패 시 잔액·소유권·적용 상태를 모두 원복한다.
- 정원 소품·수집 효과 스킨·앱 전체 색상 테마는 후속 확장이다. 효과음·교배·성장 보너스는 이 범위에 섞지 않는다.

### 화분 스킨 추가 — 2026-09-16

| 스킨 | 가격 | 모양 |
| --- | ---: | --- |
| 기본 토분 | 무료 | 식물별 기존 토분 |
| 아이보리 도자기 | 햇빛 12 | 크림색과 세로 결 |
| 세이지 물방울 | 햇빛 18 | 세이지색과 밝은 점무늬 |
| 로즈 리본 | 햇빛 24 | 장밋빛과 아이보리 띠 |

한 번 구매한 스킨은 재배·정원 화분 전체에 공통 적용하며 드래그 그림에도 반영한다. 반복 구매 없이 무료로 바꿀 수 있고 기본 토분으로도 돌아갈 수 있다. 개별 화분에 다른 스킨을 배정하는 기능은 포함하지 않는다. 배경과 동일하게 구매·적용을 분리하고 실패 시 재화와 상태를 함께 복원한다.

## 6. 저장 설계와 개발 순서

최초 햇빛 구현에서 저장 스키마를 v5로 올렸다. 이후 타이쿤은 v6, 화분 스킨은 v7이다. v7은 `owned_skins`와 `equipped_skin`을 추가하며 v6 저장의 꽃·재화·배경·비료를 그대로 보존하고 기본 토분을 지급한다. 최초 저장 전에 v6 원문을 `.json.v6-migration.bak`에 보관한다.

v5는 햇빛 잔액, 대기 빛의 ID·생성 시각·생성 출처, 생산 주기 경과 시간, 연출 순번, 최초 수집 안내 지급 여부, 구매한 꾸미기 ID, 적용한 배경 ID를 저장한다. 구매 시점에만 가격을 차감하고 재접속 시 재차 차감하지 않는다.

v4에서 이전할 때 기존 꽃·골드·씨앗·가격을 그대로 보존하고 햇빛 0·기본 배경 소유로 시작한다. 이미 보관 꽃이 있는 기존 이용자는 최초 안내 빛 1개가 대기하며, 꽃이 없으면 첫 수확 때 생성된다. 이전본을 별도 보관하고 알 수 없는 미래 버전은 기존처럼 덮어쓰지 않는다.

1. 완료: 햇빛 시계·고유 ID·상한·저장 이전과 단위 테스트.
2. 완료: 생성·클릭·터지는 효과와 기존 꽃 드래그의 입력 분리.
3. 완료: 꾸미기 구매·미리보기·적용과 저장 실패 복구.
4. 다음: 짧은 플레이로 생산 간격과 가격을 조정하고 자주 클릭하지 않아도 편안한지 확인.

완료 기준: 생성 경계·정원 비우기/꽃 추가·오프라인 상한·휴가·중복 클릭·꽃 판매 후 잔여 빛·저장 실패·구매 중복·배경 재접속 복원·320/384/520px 배치·실제 Windows 클릭/드래그를 검증한다. 개발자 `+6시간`도 햇빛 시계와 같은 시뮬레이션 경로를 사용해야 한다.

## 7. 이번 구현: 설정의 개발자 모드

- `설정 → 개발자 모드 · 별도 테스트 정원`에서 전환한다. 일반 실행에 명령줄 옵션이 없어도 진입할 수 있다.
- 일반 정원은 `garden.json`, 개발자 정원은 기존 `demo-garden.json`을 사용한다. 처음에는 새 테스트 정원으로 시작하며, 이후에는 테스트 진행을 이어 간다. 일반 정원의 꽃을 복사하거나 테스트 보상을 옮기지 않는다.
- 개발자 모드에서만 `시간 +6시간` 버튼을 사용한다. 클릭 즉시 두 재배 화분의 성장·돌봄 시계를 함께 계산하고 저장한다. 첫 물주기 전에는 자라지 않고, 휴가 중에는 성장·돌봄이 멈추는 기존 규칙을 따른다.
- 저장 실패 시 시간 이동과 게임 상태를 함께 되돌린다. 테스트 시간은 OS 시계를 바꾸지 않는다.
- 개발자 모드를 끄면 일반 정원을 다시 불러온다. 일반 정원에는 실제로 경과한 시간만 반영한다.
- 전환 대상이 다른 창에서 실행 중이거나 저장을 읽고 쓸 수 없으면 현재 정원을 유지하고 오류를 표시한다.
- 화면 제목에 개발자 상태를 표시한다. 일반 실행으로 재시작하면 일반 정원, `--demo`로 시작하면 테스트 정원을 연다. 테스트 저장이 미래 시각이면 마지막 테스트 시각에서 이어지도록 보정하며, 이 경우 종료 중 실제 경과 시간을 별도로 더하지 않는다.

개발자 `+6시간`은 기존 재배·돌봄과 햇빛 생산을 같은 시뮬레이션 경로로 진행한다. 한 번의 이동으로 대기 상한 9개까지 생성되는 동작도 검증한다.

구현 검증: Python 3.12 / PySide6 6.8.3 / Linux Qt offscreen에서 총 75개 테스트를 통과했다. 햇빛 생산 경계·상한·휴가·판매 후 잔여 빛·중복 클릭·저장 실패 복원, v4 이전, 배경 구매·적용, 개발자 시간 이동을 포함한다. 384px에서 정원·상점 실제 Qt 렌더링을 확인했다. 실제 Windows의 마우스·배율·창 동작은 수동 점검 대상으로 남긴다.
